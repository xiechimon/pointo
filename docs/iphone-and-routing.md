# iPhone sources, ScrawlKit ingest and project delivery

Read this before changing `src/phone.rs`, `src/delivery.rs`, `src/project.rs`, `src/routing.rs`, `src/web.rs`, `src/sdk.js`, `Sources/ScrawlKit/` or the helper's phone capture. The delivery recovery rules are in `AGENTS.md` because they apply even when you aren't editing this code.

## iPhone sources (`src/phone.rs`, `helper/`)

- `pointo-helper` (Swift, built by `build.rs` into `target/<profile>/`, copied and signed into `Pointo.app/Contents/MacOS` by `install-app.sh`) does SpeechAnalyzer, CoreMediaIO/AVFoundation phone capture with the mirror window, and movie decoding. Swift was chosen over objc2 bindings because SpeechAnalyzer has no Objective-C surface and `objc2-av-foundation` is not in the lockfile.
- Picker discovery (`pointo-helper devices`) reads the USB registry only: it is instant and never touches AVFoundation, so opening the picker can't raise a camera prompt or hang. The first time iPhone is chosen without Camera, Pointo closes the picker and opens the onboarding window's Camera row instead of starting the mirror (whose prompt would land under the picker).
- Live capture: the mirror window's rect (global top-left points, streamed by the helper) is the telemetry target, so ink/laser/clicks normalize into phone coordinates; inputs are re-based onto the movie's clock (`recording.startedAt`) at finish. Keyframes are selected on 320 px candidates and re-decoded from the native video at a 1600 px long edge.
- ScrawlKit ingest (`ingest_recording`, `src/delivery.rs`): the Mac answers an upload only after the bundle is built and delivered to a project folder, or after the phone's `X-Pointo-Wait` (default 25 s, max 45 s): `200 {"ok","delivered","state":"sent"|"queued"|"saved"|"processing","sessionTitle","error"?}` (`sessionTitle` is the project folder's name, or "Mac" when nothing was delivered; the field names are ScrawlKit's wire format and stay); a failed build answers 500 and forgets the recording so it can be sent again. The folder is the pinned project, else the most recent one (`phone::project_target`), else the recording is only saved; the timeline's `session` is still parsed and ignored. Copies of one recording (LAN + Tailscale, HTTP + USB, keyed by `recordedAt`) wait for the first and get its outcome. A failed delivery is `queued`: the bundle gets `.deliver.json` (`project`, `title`, tries) and the port owner retries it (15 s doubling to 30 min, for a day, then `.deliver-failed.json`); the phone never re-uploads for it, and retention skips the bundle. Over USB the Mac writes `<stamp>.delivery` (the same JSON) before `<stamp>.sent` (the project's name, all older ScrawlKit reads). ScrawlKit's `IngestReply` treats a reply without `delivered` as sent. Tests swap the outside steps through `IngestHooks`; never write into a real project folder.
- Audio for transcription is always the movie's audio exported on the asset timeline (`pointo-helper audio`). Do not feed a `.mov` straight to SpeechAnalyzer: `AVAudioFile` ignores the movie timeline and its word times drift (≈1.5 s late at 41 s on a phone recording).

## Project delivery (`src/project.rs`, `src/routing.rs`, `src/web.rs`, `src/sdk.js`)

A capture's destination is a project folder. `project::deliver(bundle, project)` copies the agent-facing files (`contact-sheet.png`, `frames/`, `frames-full/` when there is one, `pointo.json`, a timeline) to `<project>/.pointo/captures/<bundle name>/`, leaves `recording.mp4`/`.mov` and `audio.wav` in the original bundle, regenerates `summary.md` in the copy so its paths point there (its last line names the original bundle for `pointo zoom` and `pointo export`), writes the copy's path as one line to `<project>/.pointo/latest` and a short `README.md` for agents beside it, and appends `.pointo/` to the repository's `.git/info/exclude` once (never `.gitignore`; a worktree uses its common repository's). Delivering the same bundle again replaces its copy. Every delivery goes through `delivery::deliver` (same `.deliver.json` retries as iPhone) with `project::forward`, which also moves the folder to the front of `recentProjects` (at most 5, `project::push_recent`).

Choosing the folder (`routing::decide`, first hit wins; the home folder and `/` never count):

1. **Pinned**: `"project"` in config.json (absolute, `~` allowed; Settings › General › Project folder picks or clears it). `via: "pinned"`.
2. **Page**: the browser tab's live `/sdk.js` registration for its origin names a `data-directory`. `via: "page"`.
3. **Port**: the tab is on a loopback host or one of this Mac's own names (`routing::own_port`, which maps a `tailscale serve` name to its loopback port): the process listening on that port (`lsof`), its working directory, that directory's git root. `via: "port"`.
4. **Terminal**: the captured or frontmost terminal's focused folder (`routing::terminal_pane`: Ghostty 1.3+ over AppleScript), up to its git root. `via: "terminal"`.
5. Nothing: the capture stays on the clipboard.

A Screen capture reads the tab URL with `osascript` (6 s cap, for the one-time Automation prompt) and the terminal pane while the bundle is built. Routing never holds up the capture: it is copied and the island shows Completed as soon as the bundle is built, and the route acts when it arrives (`ScrawlCoordinator::route_arrived`), unless ✕ or Paste kept the capture first. A route that found a project waits out the undo window (3 s, "Sending to …"), during which a chip delivers to the most recent other project instead; a capture that found nothing (or whose `autoSend` is off) offers up to two recent projects as chips and delivers nothing until one is clicked (`via: "chosen"`). The choice is written to `pointo.json` `destination` and the summary's `For project:` line before the copy. `"autoSend": false` turns the whole ladder off (the pinned project too); an explicit pick still delivers. `pointo send <bundle> [--project <dir>]` delivers the recorded destination, else the pinned or auto ladder (`routing::project_for_send`); `pointo route --url <url>` prints the decision without delivering. A bundle written when destinations were sessions still loads: its `destination.session` is ignored and has no project. `/sdk.js` and `/web/*` on the ingest port skip the bearer check only for a loopback `Origin` from a loopback peer (`web::may_register`); `/web/registrations` needs the token. Tests swap the outside steps through `routing::Hooks` and never write into a real project.
